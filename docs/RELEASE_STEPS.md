# Release steps

Current decision, 2026-09-19: **NOT READY FOR RELEASE**. This is a reproducible verification
procedure and a publication checklist, not evidence that publication has occurred.
The [final report](FINAL_TEST_REPORT.md) records actual results; [known issues](KNOWN_ISSUES.md)
lists the remaining blockers.

## 1. Identify the candidate without changing Git history

Read `AGENTS.md`, inspect `git status --short`, `git diff --stat` and `git diff --check`.
Retain existing user changes. Do not reset, clean, force-checkout or make a commit as part
of this QA procedure. Save the candidate revision, dirty state and artifact hashes.
The audited tree was `main` at `07f65ef45ace3bd9ad52860befce5078e6af260b`, with existing
uncommitted changes; version `0.1.16-g07f65ef45ace-dirty`, versionCode `16`.

Confirm `com.projectblue.game` is the owner's intended Play package and that the next
versionCode exceeds the highest code already uploaded. Git commit count is not proof of
Play version availability. Resolve version management through the existing
[versioning process](VERSIONING.md); do not silently change identity or rewrite history.

## 2. Build and verify locally

Use JDK 17 or 21, the checked-in Gradle wrapper, Android platform 36, build-tools 35.0.0
and accepted SDK licenses. Use `local.properties` or `ANDROID_HOME` for the SDK path.
Machine paths stay outside Git. The audited minimum/target SDK is 26/36; the checked-in
AGP/Gradle pair is 8.13.2/8.13. The target API must satisfy the current
[Play requirement](https://support.google.com/googleplay/android-developer/answer/11926878).

Run each command and check its exit status before proceeding:

```powershell
.\gradlew.bat :check :lwjgl3:build :android:testDebugUnitTest :android:lintDebug :android:lintRelease :android:verifyDebugAdConfiguration :android:assembleDebug :android:bundleRelease :android:verifyReleaseBundle --rerun-tasks --warning-mode all
.\gradlew.bat :lwjgl3:run --args=--smoke
.\gradlew.bat :lwjgl3:run --args=--smoke-reload
powershell -NoProfile -File tools/test-asset-licenses.ps1
.\gradlew.bat :verifyAssetLicenses
powershell -NoProfile -File tools/verify-release-inputs.ps1
powershell -NoProfile -File tools/verify-android-artifacts.ps1
git diff --check
```

The root `:check` includes all core JUnit tests and the asset gate. World simulations
are headless Java integration tests inside that suite. There is no separate headless
Gradle module; Android unit and desktop test source sets currently have no tests.
The GL smoke commands supply separate real-window integration coverage and an isolated
save under `build/smoke/profile`. They do not modify the player's normal desktop profile.

Read warnings, not just exit codes. Reports are under `core/build/reports/tests/test/`,
`android/build/reports/` and `build/reports/problems/`. The versioning fixture test creates
temporary Git commits and was deliberately omitted from this no-commit audit.

## 3. Select the final advertising/privacy configuration

Debug uses official demo App ID and units, verified by the Gradle task. Never test by
clicking live ads. See [Google test ads](https://developers.google.com/admob/android/test-ads).
Release ads remain disabled unless the owner chooses and provisions them. The disabled
build retains a sample App ID for SDK manifest validation and empty ad unit IDs; it is
not a configured advertising release.

For advertising, provide `PB_ADS_ENABLED`, `PB_ADMOB_APP_ID`, `PB_REWARDED_AD_ID`,
`PB_INTERSTITIAL_AD_ID`, `PB_AD_AGE_TREATMENT` and `PB_UMP_UNDER_AGE` through the local/CI
environment. Do not put production identifiers in tracked files. Audience settings must
match the approved product audience; there is no per-user age flow. Use
[ADS_INTEGRATION.md](ADS_INTEGRATION.md) for supported values and callback guarantees.

Publish an owner-approved public privacy policy and expose the link in-app and in the
listing. Complete the audience, ads, content-rating and Data Safety declarations against
the exact binary and dependencies. Do not claim that an offline game has no data handling
solely because its own progression is local. See [privacy checklist](PRIVACY_CHECKLIST.md),
[Data Safety notes](DATA_SAFETY_NOTES.md) and
[Google's User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311).

## 4. Produce the signed AAB

Provision the owner's existing upload key outside the checkout through secret storage:
`PB_UPLOAD_KEYSTORE`, `PB_UPLOAD_KEY_ALIAS`, `PB_UPLOAD_STORE_PASSWORD`,
`PB_UPLOAD_KEY_PASSWORD`. All four are required together. Do not echo values, put passwords
in commands, share keys in chat or commit signing material. No key was generated by QA.
See [signing instructions](RELEASE_SIGNING.md).

Rebuild `:android:bundleRelease :android:verifyReleaseBundle` with the final environment.
Verify signing with `jarsigner -verify` and verify the expected certificate fingerprint
against the owner's upload certificate. A successful `bundletool validate` does not check
that the upload key is correct. Archive the AAB, SHA-256, version metadata and matching
`android/build/outputs/mapping/release/mapping.txt` in controlled release storage.

The unsigned verification artifact currently lives at
`android/build/outputs/bundle/release/android-release.aab`.
The debug-signed APK is `android/build/outputs/apk/debug/android-debug.apk`.
Do not describe either as a signed production release.

## 5. Test the actual minified artifact

Use bundletool/Play internal testing to generate and install device APKs from the final
AAB. Do not reuse a debug APK as evidence for R8 runtime behavior. Verify startup, all
config/assets, native loading, audio, UI texture recreation, saves and SDK callbacks.
Keep the R8 mapping for any crash report. Follow the
[Android command-line build guide](https://developer.android.com/build/building-cmdline)
and [16 KB runtime guidance](https://developer.android.com/guide/practices/page-sizes).

Complete [MANUAL_TEST_MATRIX.md](MANUAL_TEST_MATRIX.md), including API 26/API 36,
cutouts/aspect ratios, offline startup, process death, two-finger input and all 40 human
campaign/difficulty clears. Test upgrade over compatible previously signed installs
without deleting saves. Record any intentional limitations and owner acceptance.
Re-run affected regression tests and builds after fixes; update hashes and the report.

## 6. Prepare and review the store entry

Use [STORE_LISTING_DATA.md](STORE_LISTING_DATA.md) for reviewable draft copy and missing
owner inputs. Deliver the approved Play icon, feature graphic and accurate device captures;
record every export in the [asset inventory](../assets/licenses/ASSET_LICENSES.md).
Do not use QA captures as a claim of Android device verification. Complete Play Console's
current listing, rating, app access, audience, ads and privacy requirements.

Only change the decision to **RELEASE CANDIDATE READY** when every release blocker has
closure evidence. Publication/upload is a separate owner-authorized action; this audit
did not sign, upload, publish or create a commit.
